# apps/web — React SPA

Spec: PROJECT_RULES §3.2, §15. Routes: `src/routes` (file-based; `routeTree.gen.ts` is generated by the Vite plugin — do not edit). Features: `src/features/*`. UI primitives: `src/components/ui` (shadcn style, owned code).

## Stack
React 19, Vite 8 (SPA, no SSR), TanStack Router (file-based) + TanStack Query, Zustand (UI-only state), react-hook-form + `@hookform/resolvers/zod`, shadcn/ui + Radix + Tailwind CSS v4, TanStack Table, dnd-kit (keyboard sensor on), ky, Monaco (bundled locally via `monaco-editor` + `loader.config({ monaco })` — never from a CDN). Tests: Vitest + jsdom + @testing-library/react; MSW only here.

## Rules
- Selects are native `<select>` (styled): accessible and simple with react-hook-form. Radix Select is not used.
- The editor form (`features/editor/definition-form.ts`) is a flat per-step shape; `toDefinition` converts strictly (numbers/JSON typed as text are validated, never coerced) and then validates with the shared definition schema. Keep `test/definition-form.test.ts` round-trips green when adding step types.
- `lib/api.ts`: ky with `retry: 0` (no hidden retries) and `baseUrl` = page origin; errors become `ApiError` whose `issues` map onto form fields.
- `data-testid`s only where e2e needs structure (`phase-*`, `step-*`).
- Talks only to the server API (`/api`, proxied by Vite in dev → same origin). Never imports `@flowcheck/db`, `@flowcheck/test-engine` or Playwright.
- Every mutating request must send the page's `Origin` (browsers do this automatically for fetch POST) — the server rejects others.
- Validation: same Zod schemas from `@flowcheck/shared` on the client; backend errors (`details.issues[].path`) are mapped onto form fields.
- Server state lives in TanStack Query; Zustand only for UI state (sidebar, filters). Unsaved-changes warning comes from react-hook-form `isDirty`.
- Run progress: TanStack Query polling (`refetchInterval` 1 s while the run is queued/running, off otherwise). No SSE/WebSocket in v1.
- All UI text lives in `src/i18n/en.ts` (default) and `src/i18n/az.ts`; components import `t` from `@/i18n`. `az` is typed as `Dict` (= typeof en), so every new key must be added to both files. Never hardcode visible text, aria-labels or alt texts in components.
- e2e runs with an English browser locale, so e2e selectors use the English texts.
- No fake numbers, no hardcoded success, no placeholder dashboards. Loading / empty / error states for every query.
- Before starting a run, show: "This test will send real requests and may create or modify data in the test environment."
- CSS locators are shown as "fragile". `assertHidden` multi-match semantics are explained in the editor.
- Response bodies from runs are shown as text only — never rendered as HTML.
